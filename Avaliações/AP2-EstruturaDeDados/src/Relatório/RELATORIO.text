4.2 INTRODUCAO
--------------
Implementar estruturas de dados manualmente forca o programador a entender
o que acontece por baixo dos panos: como a memoria e alocada para cada no,
como ponteiros encadeiam esses nos em sequencia e qual o custo real de cada
operacao. Ao remover um no, e necessario desconectar manualmente suas
referencias para evitar nos perdidos; em estruturas circulares, o descuido
com ponteiros pode gerar loops infinitos. Programar sem atalhos torna o
desenvolvedor capaz de depurar e adaptar qualquer estrutura, inclusive
as que vem prontas nas bibliotecas padrao.


4.3 IMPLEMENTACAO
-----------------

EXERCICIO 1 - Cafeteria.java
Estruturas: Fila (FIFO) e Pilha (LIFO) com lista simplesmente ligada.

No:
int id
String descricao
No proximo  ->  aponta para o proximo no (null = fim)

Fila (FilaPedidos):
Mantem dois ponteiros: cabeca (proximo a ser atendido) e cauda (fim da fila).
enqueue: cria novo no, cauda.proximo = novo, cauda = novo
dequeue: salva cabeca, cabeca = cabeca.proximo, retorna o salvo
Caso critico: quando dequeue esvazia a fila, cauda tambem e setado null
para nao ficar apontando para um no ja removido.

Pilha (PilhaCancelados):
Mantem um unico ponteiro: topo.
push: novo.proximo = topo, topo = novo
pop:  salva topo, topo = topo.proximo, retorna o salvo
Caso critico: pop verifica se topo == null antes de qualquer acesso.

EXERCICIO 2 - Playlist.java
Estrutura: Lista duplamente ligada.

No:
String titulo, artista, album
int duracao
NoMusica anterior  ->  no anterior (null na cabeca)
NoMusica proximo   ->  no seguinte (null na cauda)

O segundo ponteiro (anterior) permite navegar nos dois sentidos.

Insercao no inicio: novo.proximo = cabeca, cabeca.anterior = novo, cabeca = novo
Insercao no fim:    cauda.proximo = novo, novo.anterior = cauda, cauda = novo
Insercao por posicao: percorre ate a posicao anterior e ajusta quatro ponteiros.

Remocao: reconecta anterior.proximo e proximo.anterior para saltar o no removido.
Caso critico: se o no removido e o atual (musica tocando), o ponteiro atual e
redirecionado para no.proximo antes da remocao.

Ordenacao: Bubble Sort trocando apenas os dados entre nos adjacentes
(titulo, artista, album, duracao), sem mexer nos ponteiros estruturais.

EXERCICIO 3 - CarrosselAnuncios.java
Estrutura: Lista circular simplesmente ligada.

No:
int id, contadorExibicoes
String empresa, descricao
NoAnuncio proximo  ->  NUNCA null em lista nao-vazia (fecha o ciclo)

Estrategia: ponteiro para a cauda (ultimo no).
Primeiro no acessado via cauda.proximo em O(1).
Insercao no inicio e no fim ambas em O(1).

Controle de rotacao: anuncioAtual avanca para anuncioAtual.proximo a cada
chamada de exibirEAvancar(), circulando infinitamente.

Casos criticos tratados:
- Lista vazia ao inserir: novo.proximo = novo (no aponta para si mesmo)
- Remover unico elemento: cauda = null, anuncioAtual = null
- Remover o anuncioAtual: anuncioAtual = alvo.proximo antes de desconectar
- Remover a cauda: cauda = anterior apos a desconexao
- Listagem sem loop infinito: do { ... } while (cursor != inicio)
  para exatamente ao fechar o ciclo, percorrendo cada no uma unica vez.

5. CONCLUSAO
------------
A maior dificuldade foi gerenciar os ponteiros nos casos extremos: listas
vazias, remocao da cabeca ou cauda, e manter o ciclo integro na lista
circular. A solucao foi tratar cada caso com verificacoes explicitas antes
da logica geral.

Na lista circular, o risco de loop infinito na listagem foi resolvido com
do-while(cursor != inicio), percorrendo cada no exatamente uma vez.

Na lista duplamente ligada, a ordenacao por troca de dados (nao de nos)
simplificou bastante a implementacao sem perda de corretude.

O aprendizado principal foi entender que estruturas de dados sao apenas
objetos conectados por referencias, e que o programador e inteiramente
responsavel por manter essas referencias consistentes em toda operacao.
